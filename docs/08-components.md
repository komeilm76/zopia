# 🧱 Components

A spec keeps DRY with **components** — named, reusable schemas referenced via
`$ref` (Swagger 2.0: `definitions`; OpenAPI 3.x: `components.schemas`).
Components can reference *other* components, and even themselves (cycles).
This document defines how zopia treats them in the generated tree.

## 🔗 Local references

OpenAPI local JSON Pointer references are resolved only when their target exists
in the same document. The resolver supports `#` for the document root and the
standard `~1` and `~0` pointer escapes. External references and invalid pointer
escapes are rejected explicitly rather than silently dropped. Component files
and reusable endpoint references are part of the full rendering phase.

## ⚙️ The two options

> 🎯 **T-8 / T-9** — both options are **booleans, both default `false`**, and
> `useComponentAsReference` only makes sense when `insertComponents` is `true`.
> Component files and exact endpoint schema-reference imports are implemented;
> nested component-reference imports are recursively supported across the complete Engine ② schema surface, including objects, arrays, compositions, conditionals/refinements, nullable schemas, enums, constants, named schema maps, and additional-property schemas. Direct aliases retain distinct lazy identities for reverse conversion, and direct/mutual cyclic imports use lazy schemas.

| ⚙️ `insertComponents` | ⚙️ `useComponentAsReference` | 📂 What is generated | 📄 What endpoint files do |
| :---: | :---: | --- | --- |
| `false` | `false` *(forced)* | nothing extra | inline every referenced schema occurrence (R-403) — **fully self-contained** |
| `false` | `true` | 🛑 **invalid** → `ZOPIA_CONFIG_INVALID` ("enable `insertComponents` first") | — |
| `true` | `false` | `components/**` written | still **inline** (components exist as standalone files, but endpoints do not import them) |
| `true` | `true` | `components/**` written | **import** components — single source of truth, no duplication |

> 📌 **Rule R-801** — `insertComponents: true` emits **every** declared
> component (even ones no operation references) — the tree mirrors the spec.
> Unused components are still useful documentation, and the mirror keeps the
> reverse conversion complete.

## 📂 Layout (when `insertComponents: true`)

Components land in `api_docs/components/`, one directory **per component,
named exactly as declared** (case preserved — the name is data, D-06):

```text
api_docs/
├── .zopia-manifest.json
├── components/
│   ├── index.ts              # 🚪 barrel — re-exports every component
│   ├── CreateUser/
│   │   └── index.ts          # export const CreateUserSchema = …
│   └── User/
│       └── index.ts          # export const UserSchema = …
├── health/get/index.ts
└── users/{userId}/
    ├── get/index.ts
    └── patch/index.ts
```

### 📄 Component file format

```ts
/** Generated by zopia — do not edit by hand. */
import { z } from 'zod';

export const UserSchema = (() => { /**
 * User
 * A user account
 */
const UserSchema = z.object({ ["email"]: z.string().email(), ["id"]: z.string().uuid(), ["nickname"]: z.string().nullable().optional(), ["role"]: z.enum(["admin","viewer"]).optional() }).strict().meta({"title":"User","description":"A user account"}); return UserSchema; })();

export default UserSchema;
```

Component expressions are emitted through the same complete Engine ② converter
used for endpoint schemas, then structural component references are replaced by
imports. Constraints such as `not`, property-name checks, tuple/array bounds,
`uniqueItems`, and `$ref` siblings therefore remain live runtime validation;
root and nested annotations (`deprecated`, access flags, XML/external docs, and
`x-…`) remain Zod metadata for reverse conversion.

### 🚪 The barrel

`components/index.ts` re-exports every component in name order:

```ts
export { CreateUserSchema } from "./CreateUser/index";
export { UserSchema } from "./User/index";
```

> 📌 **Rule R-802** — endpoint files import components **through the barrel**
> (`from '<relative>/components/index'`), never from a deep path. A component
> named `index.ts` (case-insensitively) is rejected before any write because its
> required directory would collide with this barrel file. The relative
> prefix is computed per file and per mode:
>
> | mode | file depth | import |
> | --- | --- | --- |
> | directory · `users/{userId}/get/index.ts` | 3 | `import { UserSchema } from '../../../components/index';` |
> | flat · `users-{userId}/get/index.ts` | 2 | `import { UserSchema } from '../../components/index';` |

## 🔗 Component → component references

When a component uses another component, the dependency becomes a **relative
import between component files** — the same `$ref` graph, now in TypeScript:

```ts
// components/Post/index.ts
import { AuthorSchema } from '../Author/index';

export const PostSchema = z.object({
  title: z.string(),
  author: AuthorSchema, // ⤵ $ref #/components/schemas/Author
});
```

| # | Rule |
| --- | --- |
| R-811 | 🧩 Import graph mirrors structural `$ref` edges exactly (R-402); `$ref`-looking values inside `default`, `example(s)`, `enum`, `const`, and `x-…` data stay literal. Component files import only *component files* (never endpoint files), and valid `$ref` siblings retain their runtime constraints and annotations |
| R-812 | 🌀 **Cycles** (e.g. `Comment.replies → Comment`) become `z.lazy(() => CommentSchema)` on the *cyclic edge only* — the file still loads (R-402). Direct aliases also use a lazy wrapper so alias and target remain distinct runtime identities during reverse conversion |
| R-813 | 📦 Components imported from the barrel by endpoints never create import cycles: components never import endpoints (R-811) |

## 📄 Generated endpoint files with `useComponentAsReference: true`

```ts
/** Generated by zopia — do not edit by hand. */
import { z } from 'zod';
import { makeApiConfig } from 'km-api';
import { UserSchema } from '../../../components/index';

export const getUser = makeApiConfig({
  method: "GET",
  pathShape: "/users/{userId}",
  operationId: "getUser",

  responseContentType: "application/json" as unknown as import('km-api').IResponseContentType,
  deprecated: 'YES',
  auth: "YES",
  summary: "Get a user",
  description: "Returns one user",
  tags: ["#users"],
  examples: JSON.parse("{\"response\":{\"200\":{\"default\":{\"value\":{\"email\":\"admin@example.test\",\"id\":\"22ccbc6a-436b-4b1c-9e64-7440ce63a90e\",\"role\":\"admin\"}}}}}"),
  request: { body: z.any(),  params: z.object({ ["userId"]: z.string().uuid() }), query: z.object({  }), headers: z.object({ ["X-Trace-Id"]: z.string().optional() }), cookies: z.object({  }) },
  response: { 200: UserSchema, 404: z.object({  }).passthrough() },
});

export default getUser;
// Source: "Admin API v1.2.0"
```

With references on, each component export is imported once per endpoint file
and reused at every matching identity (R-403). Non-component schemas remain
inline.

## 🔄 Reverse conversion (engine ④)

| # | Rule |
| --- | --- |
| R-821 | 🧱 Engine ④ rebuilds `components.schemas` from the manifest in **every** mode: `file` set (components mode) → the component file is imported and converted with engine ① (developer edits win); `file: null` (default mode) → the manifest `schema` is re-emitted verbatim (R-655/R-751) |
| R-822 | 🔗 Endpoint use-sites of imported components become `$ref: "#/components/schemas/<Name>"` again from runtime Zod identity; changing the component used in generated code changes the emitted `$ref`. RFC 6901-escaped names are decoded for imports and re-escaped in output, and direct aliases retain their `$ref` sibling keywords as Zod metadata. |
| R-823 | 🌀 `z.lazy` cycles serialize back to self `$ref`s — recursion round-trips |
| R-824 | 📸 Component annotations and direct-`$ref` siblings are emitted as Zod metadata when a component file exists, so code remains authoritative; only `file: null` components use the manifest schema snapshot |

## 🚫 Phase 1 scope (documented limits)

Reusable non-schema objects (`components.parameters`, `components.responses`,
`components.examples`, and Swagger globals) are resolved at endpoint use sites
for generated km-api code. The manifest preserves their declarations and ref
placements, so engine ④ restores reusable identity. Phase 2 is only needed to
emit those objects as standalone generated files.

| 🧩 Thing | Phase 1 behaviour | When |
| --- | --- | --- |
| external refs to other files | `ZOPIA_REF_EXTERNAL` | Phase 2 |
